# 服务重启后的任务跟踪恢复

Web UI 会记录自己观察到的运行轮次，在连接中断或服务重启后通过只读查询恢复跟踪。后台核对不会重跑任务、调用 `thread/resume`、接管写入或重启 daemon；页面重新打开当前任务时仍使用原有的查看与订阅流程。

生产环境默认将记录保存在可信设备文件旁的 `task-recovery.json`，也可用 `CODEX_PWA_TASK_RECOVERY_FILE` 指定独立路径。普通测试/开发环境默认只存内存，显式指定路径后才持久化。文件原子替换、权限为 600，只保存任务 ID、轮次 ID、状态与观察时间，不保存消息、命令、目录或错误正文；重复安装保留已配置路径。

## 状态与范围

- 浏览器单独记录实时事件流的连接状态。普通 HTTP 轮询可以读取任务状态，但在事件流断开、重连或尚未打开时，不能把连接提示改成“服务器已连接”；停止、连接错误和心跳超时会清除该连接标记。重叠轮询与重连读取的晚到响应已有浏览器回归覆盖。
- 启动时，原先未结束的任务先显示为“待核实”，不能仅凭旧记录判断仍在运行。
- 重连时立即查询，之后每个未结束任务约每 15 秒核对一次，最多 4 个任务并行，单次只读取最新轮次元数据。查询前后重新检查目录授权和任务状态。
- `active` 与 `inProgress` 一致时确认运行；已知轮次的 `completed`、`failed`、`interrupted` 与非活动任务状态一致时确认结束。加载状态、轮次或查询结果不一致时继续待核实；读取失败不代表完成。
- 恢复期间收到新实时事件，会使较早的查询失效。旧轮次的完成事件不能清除较新的运行轮次。
- 最多保留 256 个任务，优先淘汰已结束记录；未结束任务超过上限时淘汰最早记录，并在诊断中显示计数。损坏的原文件会保留，内存跟踪继续运行，界面报告存储异常。
- `/api/status` 和任务详情中的“桥接协议 → 任务恢复”提供运行、待核实、存储健康与超限信息。诊断脚本检查文件格式和权限。

恢复确认使用独立事件通知页面，页面重新读取权威状态，不把旧轮次的结果直接写入当前对话。已启用的 Web Push 可以在没有浏览器连接时发送恢复结果；它与实时完成事件共用送达去重记录。未配置推送时不会因此启用外部服务。

恢复只覆盖已有记录的任务，不扫描全部用户历史，不补发整个对话。若旧记录对应的轮次已经被新的已结束轮次取代，会保留待核实而非猜测旧轮次结果。交互审批请求不在此记录中；CLI 0.153.2 的独立验收确认，Web UI 重启后重新订阅任务会由仍在运行的 daemon 重发原待审批请求，详见下文。其他 CLI 版本仍须分别验证。

共享 daemon 模式下，Web UI 重启可以与任务执行分离；隔离 app-server 模式随 Web UI 退出可能终止实际执行，本功能不能保证其任务继续运行。这里只恢复跟踪，不承诺恢复被终止的计算。

## 真实运行任务的只读恢复验收（2026-09-16）

## 已有验证及限制

页面恢复连接与任务状态同步是两个独立结果。SSE 建立后，只有状态接口、任务列表及当前任务的必要读取确实完成，才提示“任务状态已同步”；失败会提示“尚未同步”并以 3、6、12、24、30 秒间隔重试，之后最多每 30 秒一次。同一连接共用正在进行的恢复请求，持续失败只提示一次。页面隐藏时暂缓重试，回到前台继续；退出登录或连接失效会取消计时器，并使旧连接的响应和延迟提示失效。

同步期间收到重放缺口会要求再读一次最新状态，避免用缺口通知之前发起的快照宣称恢复完成。历史上下文继续保留阅读位置，正文更新推迟到返回最新内容。`test/event-connection.test.mjs` 使用受控计时器验证这些竞态与退避；移动 Chrome 注入状态接口 503，核对自动重试及实际提示，并延迟一个成功响应到断线之后，核对它不会将界面误标为已连接。

浏览器另有最多 200 条的轻量活动快照，只保存任务 ID、状态与观察时间。刷新列表时，恢复提示分别报告仍在运行、等待操作、空闲、异常和待核实；`idle` 只证明当前空闲，不能证明上一轮成功。`notLoaded`、未知状态以及未出现在搜索/分页结果中的任务继续待核实，记录不会因为一次局部列表响应而丢失。已确认的轮次结果仍由实时完成事件或服务器恢复核对提供。

任务列表、活动记录、页面通知及 Web Push 的核心状态用语统一由 `public/status-display.js` 管理。列表将“空闲”“已保存，未加载”和“状态待核实”分别筛选；任务异常使用同一分类逻辑，支持规范的 `systemError`。未知 `turn/completed` 状态不发送成功通知，也不据此清除当前运行轮次。停止统一显示为“已停止”，失败轮次即使没有附带错误对象也显示失败提示。错误正文留在任务中，页面与服务器推送均使用固定状态文案。

`test/task-snapshot.test.mjs` 验证不误判完成、缺失/未知状态、部分列表保留与记录上限；移动 Chrome 验证真实页面的混合恢复提示、三个筛选、通知标题以及没有错误详情的失败轮次。这些范围使用受控协议数据，不等同于真实外部客户端验收。

`test/task-recovery-http.test.mjs` 使用真实独立 PWA 进程、HTTP、持久文件和 Unix WebSocket 模拟 daemon，覆盖 SIGKILL 后恢复、桥接重连、无浏览器/SSE 时轮询发现完成、结束结果不重复广播、目录越界丢弃、延迟旧完成事件。捕获的恢复 RPC 只有 `initialize`、`thread/read`、`thread/turns/list`，最新轮次使用 `itemsView: "notLoaded"`。
