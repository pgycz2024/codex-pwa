# 可选后台推送

Web Push 让服务器在页面关闭后继续发送任务完成、失败、中止或等待审批的提醒。它不需要修改 Codex API Key，也不需要把 PWA 开放到公网；浏览器访问 PWA 的地址仍可限制在私网，但必须使用浏览器信任的 HTTPS（localhost 可用于开发）。服务器和设备都需要能访问浏览器厂商的推送服务。

## 配置

1. 启用现有的 Web UI 密码/可信设备登录，准备 HTTPS 访问地址。普通私网 HTTP 继续支持原有远程控制，但不能订阅 Web Push。
2. 在 PWA 安装目录生成一次专用 VAPID 密钥，提供维护者自己的联系地址：

   ```bash
   npm run setup:push -- --subject mailto:you@example.com
   ```

   可使用 `--output /absolute/private/path/push-vapid.json` 指定文件。默认写入用户配置目录的 `codex-pwa/push-vapid.json`，权限 600。脚本不打印私钥、不覆盖已有密钥、不修改服务配置、不重启任何服务。重复执行保留原有密钥及联系人。VAPID 公钥会提供给浏览器；私钥只保存在该 Linux 用户的服务器文件中。

3. 将脚本打印的 `CODEX_PWA_PUSH_CONFIG_FILE="..."` 加入该用户的 PWA 环境配置，在计划中的 PWA 更新/重载时应用；共享 Codex daemon 不需要重启。订阅默认保存在可信设备文件旁的 `push-subscriptions.json`（权限 600），可用 `CODEX_PWA_PUSH_STORE_FILE` 指定。重新运行安装器会保留这些可选配置。
4. 用支持推送的浏览器登录 HTTPS Web UI，在侧栏“浏览器通知”中选择“开启后台推送”。部分手机需要先把网页添加到主屏幕。每台设备分别开启，可在同一面板关闭；页面通知仍可单独使用。

不要随发布包分发 VAPID 私钥或订阅文件。备份并保留密钥；更换公钥后，各设备需要重新开启推送。联系人用于浏览器推送协议，不是任务结果邮件的收件地址。

通知设置会分别显示等待权限、浏览器注册和服务器保存进度。浏览器注册超过 10 秒时会显示等待说明；这不是失败或取消，浏览器的注册调用仍在进行。可以关闭设置窗口并保持当前页面打开，结果会在页面提示；重开设置窗口仍显示当前进度，不会重复注册。只有服务器确认保存成功后才显示已开启。

## 出站代理

如果服务器只能通过代理访问厂商推送服务，可以在上述权限为 600 的私有 `push-vapid.json` 中保留现有三项 VAPID 字段，额外加入 `proxy`，例如 `"proxy": "http://127.0.0.1:3128"`。支持 HTTP/HTTPS CONNECT 代理及其 URL 中的认证信息；不支持 SOCKS URL、路径、查询参数或片段。删除该字段或设为空字符串恢复直连。配置在计划中的 PWA 重载后生效，不需要重启 Codex daemon；重复执行密钥生成脚本会保留既有代理和密钥，不打印代理凭据。

代理只控制 PWA 服务器的出站投递；浏览器/手机自身到厂商注册与接收服务的连接仍须可用。程序不自动采用终端的 `HTTP_PROXY`、`HTTPS_PROXY` 或 `ALL_PROXY`，避免隐式改变部署网络。推送地址依旧只能属于允许的浏览器厂商；设备不能通过订阅 API 指定代理。代理 URL、凭据及原始代理错误不返回前端，也不写入订阅文件或公开诊断。

## 发送与撤销

- 发送依赖 PWA 桥接服务仍在运行，并且收到相应任务的 app-server 事件。关闭网页不影响 PWA 已经管理的运行中任务及待审批请求；此功能不会为了通知自动接管其他客户端的任务。
- 发送前重新核对可信设备登录、任务当前目录授权和审批是否仍待处理。设备退出、撤销、密码改变或登录过期后停止向旧会话发送；已在推送服务中接受的通知无法远程撤回。
- 提醒内容仅含任务 ID、固定状态文案和事件摘要标识，不含消息正文、文件内容、命令、路径或原始错误详情。数据使用标准 `aes128gcm` 加密与 VAPID 签名，推送地址限于受支持的浏览器厂商 HTTPS 服务。
- 相同事件的成功投递记录短期持久化，避免桥接服务重启后立即重复推送。队列、并发、订阅数量及投递记录均有上限；有效期 5 分钟。网络/429/5xx 故障至多重试一次，遵守不超过 30 秒的 Retry-After；更长等待留给后续事件，不无限重试。404/410 失效订阅会移除，面板可重新开启。
- 当前任务正在可见页面中时，worker 通知页面刷新状态；其他任务或页面已隐藏/关闭时显示通知。点击提醒复用已有应用页面并保留草稿，或打开同源任务地址。平台省电、免打扰和推送服务网络会影响实际送达。

`npm run doctor` 可检查已配置的 VAPID 文件格式和私有权限。通知面板显示此设备订阅状态及最近投递失败信息；接口不返回订阅地址或私钥。页面通知和后台推送在此设备上避免重复触发。

## 实际网络与 HTTPS 浏览器探测（2026-09-16）

以独立密码、设备会话、VAPID 密钥、Chrome 配置目录和本地 HTTPS 入口运行完整 PWA；临时证书只通过该测试浏览器的公钥摘要选项接受，没有修改系统信任或现有浏览器配置。HTTPS 登录、真实 Service Worker 安装和安全上下文已验证。任务桥接使用受控 daemon，仅供投递触发，不连接生产 daemon；没有接入现有设备。

网络预检发现当前环境直连 FCM 443 超时，经已有出站代理可取得 FCM HTTP 响应；这只证明连接能力，不代表投递成功。原实现不传递私有配置中的代理字段，已由回归先复现再修复。新增实际 CONNECT 代理回归使用真实 `web-push` 传输，确认请求进入所配置代理、代理认证正确、403 拒绝被准确记录且不泄露凭据；测试代理不向外转发，因此它不是厂商成功投递证据。

在直连和显式代理两次探测中，原生 `PushManager.subscribe` 都没有在 45 秒内返回结果。未取得真实订阅地址，未执行向厂商的实际通知投递；没有收到足以确定根因的浏览器错误，不能将其直接归因为某个网络端口、代理或无头浏览器限制。临时 PWA、HTTPS 入口和浏览器已停止，私有诊断记录保留，生产推送未启用。后续仍需在能够成功注册的实际浏览器/手机上完成 R06，不用手工构造订阅或 DevTools 注入替代。

代理改动的专项检查 15/15 通过；最终 `npm run release:verify` 为 270/270，121 个模块、227 处本地导入、160 个清单文件、隐私扫描及完整暂存包运行检查通过（63 个前端文件、68 个缓存 URL）。应用版本保持 0.18.15，Service Worker 保持 v113；生产 PWA/proxy 与共享 daemon 均未重启，既有 VAPID/订阅配置未改动。
