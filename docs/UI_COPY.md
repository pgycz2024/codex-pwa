# 界面文案维护

当前界面使用简体中文。Codex、Goal、API、HTTP、PDF、CLI、模型名称、推理参数名和文件单位保留原名。任务列表和任务操作统一称为“任务”；停止一轮执行使用“停止”，设备退出登录使用“退出”，撤销信任使用“撤销”。审批的“本次会话批准”保留上游会话范围含义。

## 文案来源

`public/ui-copy.js` 中的 `UI_COPY` 是设置、文件/预览、目录授权、设备、Goal、审批、任务操作、历史节点、诊断与各弹窗的产品文案目录，也包含服务端对应的参数校验提示。键按功能和调用位置分组；改文字时保留键，避免同时修改调用处。`common.*` 保存共用操作名称。

任务状态的协议解释继续集中在 `public/status-display.js`。该模块仍区分空闲、待核实、运行和成功；不能为了文案一致把不同状态合并。协议枚举、模型参数、HTML 控件值、错误码和请求身份均与显示文字分开。

动态文本通过 `uiText(key, ...values)` 读取，例如：

```js
uiText("files.deleteSelectedFileBrowserEntries.title", selectedPaths.length);
// 删除选中的 3 个项目？
```

目录中的 `{0}`、`{1}` 等占位符按调用参数顺序替换。用户传入的路径、文件名、任务名称、回答和错误详情只作为数据，不会再次解释成模板；界面继续用 `textContent` 呈现。键不存在或缺少参数会明确抛错，检查会核对源码中的引用与目录模板。

## 静态 HTML

`public/index.html` 和 `public/file-preview.html` 随包保留完整可读文本，JavaScript 尚未加载时也有按钮名称和无障碍标签。文本节点用 `<!--copy:key-->…<!--/copy-->` 标记；`aria-label`、`title`、`placeholder` 用对应的 `data-copy-*` 属性绑定。同步仅更新明确标记的文字，不替换控件、图标、事件或表单值。

修改目录后运行：

```bash
npm run copy:sync
npm run copy:check
```

同步脚本对目录中的文字做 HTML 转义。`npm run check` 与发布验证包含同步检查，静态页面残留旧文案时会失败。新增弹窗文案应同时加入目录和标记；新增 JavaScript 文案应调用 `uiText`，并按功能保留稳定的键。

## 验证边界

`test/ui-copy.test.mjs` 检查静态同步、按钮/图标保留、可访问名称、插值边界、键与参数完整性、设置和 Goal 校验及协议枚举保留。移动 Chrome 覆盖实际确认框的中文标题和 `zh-CN` 标记，以及现有 17 个弹窗、审批、文件和任务操作。

来自 Codex 的正文、模型说明、工具输出、文件内容与未知上游错误详情保持原始内容；日志和底层协议字段可以保留英文。屏幕阅读器实机效果继续按 R11/R12 验收。
