# 发布生命周期验收

本记录保留 0.19 系列的开发及发布前验收证据。正式分发使用经过隐私清洗的提交、版本标签和带 SHA-256 清单的发布文件；各阶段证据须对应其明确的版本与内容摘要。

## 自动验收入口

```bash
node --test test/deployment-lifecycle.test.mjs
npm run release:verify
npm run release:candidate
```

部署测试实际执行当前安装器和更新器、`npm ci`、候选检查、ZIP 解包、Git fast-forward、目录切换、回滚和本机 HTTP 请求。测试使用带空格的临时安装路径及独立配置目录；无外部依赖的候选应用用于注入故障。Git 提交和远端仅存在于测试创建的临时仓库，不操作维护仓库或外部 Git 服务。服务由测试进程管理，`systemctl`、Codex 登录/daemon 查询和 unit 验证被替换为测试接口。不会控制生产 PWA 或共享 daemon，也不使用真实登录凭据。

## 本轮覆盖

| 场景 | 验收结果要求 |
| --- | --- |
| 安装与重复安装 | 实际 HTTP 服务启动；工作目录和 daemon socket 配置正确；现有密码、用户名和可信设备不变 |
| 从其他目录运行安装器 | 使用绝对脚本路径启动时，依赖仍安装到 PWA 目录 |
| Codex daemon 初始化失败 | 保留上游错误并解释前提及已有 daemon 复用方式；不更改 PWA 配置或操作其服务 |
| 成功更新 | HTTP 返回候选版本，完整 Service Worker 与包内文件一致；旧程序树完整保留 |
| 候选检查失败 | 保持原安装与原服务，不执行服务重启 |
| ZIP 文件内容与清单不一致 | npm 执行之前拒绝，原安装不变 |
| 旧 Service Worker、错误运行版本或 `ok:false` | 拒绝更新并恢复旧版本，只有旧版本健康和资源核对通过才报告回滚完成 |
| 候选服务启动失败 | 恢复旧目录与旧服务，保留失败候选以供排查 |
| 旧版本也无法恢复启动 | 恢复旧目录，但明确报告服务恢复未确认，不输出“回滚完成” |
| 同秒连续更新 | 生成不同备份目录，各自保留完整旧版本 |
| 更新互斥 | 第二个更新进程被拒绝，不切换目录或重启服务 |
| Git 成功更新及重复运行 | 独立候选 checkout fast-forward 后切换，保留原 HEAD 备份、相对 remote、Git 配置和 ignored 本机文件；已是最新提交不重启 |
| Git 候选测试或启动失败 | 原程序目录和 HEAD 保持原版本或恢复原版本，并核对实际 HTTP 服务 |
| Git 脏工作树、分叉历史及检查期间的新改动 | 拒绝切换；原 HEAD 和本地改动保留，不重启原服务 |
| 关联 worktree | 拒绝移动主目录，原目录及关联工作树继续可用 |
| 多安装备份保留 | 仅修剪属于当前安装的新格式备份；其他安装和归属未明的旧备份保持完整 |

发布验证还会对真实暂存包使用相同的内部清单校验器，确认全部普通文件都在清单内且摘要匹配，拒绝缺失文件、额外文件、符号链接、越界路径及重复清单条目。包内清单用于完整性核对，不能代替从可信 Release 获取 ZIP 并核对外部 SHA-256。

## 可审阅的本地候选包

`npm run release:candidate` 允许未提交工作树，在完整测试、模块检查、隐私扫描、清单与暂存包实际运行验收通过后，保留候选 ZIP、`CANDIDATE.json` 和 `SHA256SUMS.txt`。每次在独立的 `dist/candidate-*` 目录生成，不覆盖以前的候选或正式包，不创建 Git 提交、标签、bundle 或外部 Release。

候选元数据记录源 HEAD、构建开始时是否有未提交改动、当前版本，以及 ZIP、包内清单和 Service Worker 的 SHA-256；外部校验文件同时覆盖 ZIP 与元数据。候选仍使用工作树现有版本号，因此以摘要识别具体快照，不能仅看健康接口版本。正式打包仍要求干净工作树和指向 HEAD 的对应标签。
